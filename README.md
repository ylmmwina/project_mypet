# 🐾 MyPet: Навчальний Fullstack Tamagotchi Проєкт
MyPet — це повноцінний навчальний Fullstack-застосунок, розроблений у стилі класичних ігор-тамагочі, для відпрацювання принципів ООП та WebSockets.

## 🚀 1. Розвиток проєкту: Підсумки 2 семестру
У другому семестрі проєкт MyPet перейшов від базової тамагочі-механіки до розвиненої ігрової екосистеми з автоматизацією та тестуванням:
* **Система реєстрації та автентифікації:** Впроваджено механізм створення акаунтів, що дозволяє користувачам керувати кількома улюбленцями та зберігати прогрес у БД (SQLite).
* **Система квестів:** Впроваджено систему завдань із фоновим трекінгом прогресу, що автоматизує нарахування нагород (XP/монети) та забезпечує захист від повторного отримання бонусів.
* **Тестування:** Реалізовано комплексне покриття інтеграційними тестами (50+ кейсів на Jest/Supertest), що гарантує стабільність критичних шляхів системи (реєстрація, економіка, виконання квестів).
* **Економіка та Mystery Box:** Розроблено механіку випадкових предметів із системою рідкості (rarity), інтегровану з інвентарем користувача.
* **Динамічне середовище:** Реалізовано зміну локацій, що оновлюються в реальному часі залежно від стану улюбленця або дій гравця.
* **Інфраструктура (CI/CD):** Налаштовано pipeline на GitHub Actions для автоматизації перевірок якості коду та виконання тестів при кожному `push` чи `pull request`.

## ⭐ 2. Базова реалізація: Підсумки 1 семестру
Основні досягнення 1 семестру:
* **Принципи ООП:** Практична демонстрація інкапсуляції, поліморфізму та наслідування.
* **Архітектура:** Реалізовано чіткий поділ на моделі, роути та утиліти.
* **Модульність:** Повне використання ES Modules.
* **Тестування:** Налаштовано та реалізовано тестування (Jest, Supertest).
* **Документування:** Налаштовано генерацію документації через JSDoc / Doxygen.
* **Real-Time:** Реалізовано синхронізацію в реальному часі через WebSockets (Socket.IO).

### 2.1 Ігрові механіки
Гравець доглядає за улюбленцем (Кіт, Пес, Мавпа), контролюючи його життєві показники.

| Показник | Діапазон | Опис |
| :--- | :--- | :--- |
| **Health** | 1–100 | Здоров'я. Мінімум 1 (улюбленець не вмирає). |
| **Hunger** | 0–100 | Голод (0 — ситий, 100 — голодний). |
| **Happiness** | 0–100 | Щастя. Впливає на здоров'я. |
| **Energy** | 0–100 | Енергія. Витрачається під час активностей, відновлюється уві сні. |
| **Cleanliness** | 0–100 | Чистота улюбленця. |
| **Coins** | 0+ | Внутрішньоігрова валюта. |
| **XP** | 0+ | Досвід, що нараховується за активності. |
| **Level** | 1+ | Рівень улюбленця. |

## 🏗️ 3. ООП Архітектура та Дизайн

### 3.1 Інкапсуляція та Моделі
- `backend/models/pet.js` — модель Pet, інкапсулює стани та логіку;
- методи: `pet.feed()`, `pet.live()`, `pet.sleep()`, `pet.finishGame()`;
- Game Loop у `backend/server.js` викликає `pet.live()` через `setInterval`.

### 3.2 Поліморфізм
- `applyItemEffects` (`backend/shop/shopItems.js`) працює по-різному для різних типів предметів;
- Mini-game використовує різні спрайти залежно від типу улюбленця.

### 3.3 Real-Time
- Socket.IO надсилає `pet-update` щоразу після зміни стану улюбленця;
- Live-оновлення дозволяють синхронізувати стан між клієнтом і сервером.

## 🧪 5. Тестування (Jest & Supertest)
Запуск тестів: `npm test`

Поточний набір тестів охоплює:
1. **Core:** Створення улюбленця, годування, сон, міні-ігри.
2. **Economy:** Магазин, інвентар, нарахування монет/XP.
3. **Integration:** Повний цикл системи квестів (трекінг, нагородження, захист від повторного claim, скидання).

## 🚀 6. CI/CD та автоматизація (GitHub Actions)
У проєкті налаштовано **GitHub Actions** для автоматизації перевірок якості коду.
* **Workflow:** Конфігурація знаходиться у файлі `.github/workflows/node-tests.yml`.
* **Автоматизація:** Кожен `push` або `pull_request` у гілку `main` автоматично запускає:
    1. `npm ci` — чисте встановлення залежностей.
    2. `npm test` — виконання набору інтеграційних та unit-тестів (Jest/Supertest).
* **Результат:** Це дозволяє перевіряти стабільність проєкту перед злиттям змін та гарантує, що нові функції не "ламають" базовий функціонал.

## 🛠️ 8. Встановлення та запуск

Для звичайного локального запуску:

```bash
npm install
```

Для чистого встановлення залежностей, як у CI:


```bash
npm run start:backend
```
